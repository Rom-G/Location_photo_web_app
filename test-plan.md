# Тест-план. Регрессионное тестирование веб-приложения «Location»

## 1. Введение

Документ описывает план регрессионного тестирования веб-приложения «Location» на тестовом стенде и ретеста ранее зарегистрированных дефектов. Тест-план составлен до начала прогона и фиксирует объём, подход, критерии начала и завершения, а также предполагаемые риски.

## 2. Объект тестирования

Веб-приложение «Location», развёрнутое на тестовом стенде (test_stand).

Функциональные области в зоне проверки:

- редактирование профиля: открытие и закрытие окна редактирования, поля «Имя» и «Занятие», валидация длины значений, активность кнопки «Сохранить», сохранение данных;
- карточки мест: открытие карточки, просмотр изображения, отметка «Нравится»;
- главная страница: отображение элементов, добавление и удаление карточек, скролл галереи.

## 3. Цели и задачи

- Выполнить регрессионное тестирование по готовым тест-кейсам.
- Провести ретест ранее зарегистрированных дефектов BR-001 — BR-015.
- Регистрировать новые дефекты с продолжением нумерации (BR-016 и далее).
- Подготовить сводный отчёт о результатах прогона и ретеста.

## 4. Объём работ

**In scope:**

- функциональное регрессионное тестирование перечисленных областей по готовым кейсам;
- ретест дефектов BR-001 — BR-015 после исправлений;
- регистрация новых дефектов по результатам прогона.

**Out of scope:**

- автоматизация тестирования;
- нагрузочное тестирование;
- тестирование безопасности;
- кросс-браузерное и кроссплатформенное тестирование;
- тестирование API.

## 5. Подход

Тестирование выполняется вручную по готовым тест-кейсам. По каждому кейсу фиксируется статус: Passed / Failed / Blocked. Для Failed-кейсов регистрируется баг-репорт со связью с ID кейса.

Ретест проводится по зарегистрированным дефектам BR-001 — BR-015: дефект проверяется по шагам воспроизведения из репорта. По результатам ретеста дефект переводится в статус Closed (не воспроизводится) или Reopened (воспроизводится). Если проверка дефекта невозможна по независящей причине (например, отсутствует элемент интерфейса), дефекту присваивается статус Blocked с указанием причины в комментарии.

## 6. Критерии начала и завершения

**Критерии начала:**

- тестовый стенд доступен;
- окружение подготовлено (см. раздел «Окружение»);
- комплект тест-кейсов и список дефектов на ретест переданы.

**Критерии завершения:**

- все тест-кейсы выполнены, статусы зафиксированы;
- ретест всех дефектов из списка BR-001 — BR-015 проведён, статусы обновлены;
- новые дефекты зарегистрированы;
- сводный отчёт о результатах оформлен.

## 7. Окружение

- ОС: Windows 11 Pro 24H2
- Браузер: Chrome 157.0.8103.52 x64
- Стенд: test_stand

## 8. Риски и меры по их снижению

| Риск | Мера |
|---|---|
| Часть функциональности не реализована на тестовом стенде — соответствующие кейсы и ретесты выполнить не удастся | Фиксировать статус Blocked с указанием причины в комментарии; по завершении отразить в сводном отчёте |
| Стенд недоступен или нестабилен во время прогона | Фиксировать время недоступности; приостановить прогон и возобновить после восстановления; недоступность учесть в сроках |
| Исправления дефектов из ретеста могут быть развёрнуты на стенде не одновременно | Ретест проводить по актуальному состоянию стенда; при обнаружении расхождений фиксировать время проверки |
| Ограниченное время на прогон | Приоритизировать кейсы и дефекты по критичности функциональных областей |

## 9. График работ

- Подготовка: до начала прогона.
- Регрессионный прогон и ретест: в течение отведённого на спринт периода.
- Оформление сводного отчёта: по завершении прогона.

## 10. Артефакты

- Комплект тест-кейсов регресса (таблица с результатами прогона).
- Баг-репорты по ретестируемым дефектам (BR-001 — BR-015).
- Баг-репорты по новым дефектам (BR-016 и далее).
- Сводный отчёт о результатах прогона и ретеста (в README репозитория).
